[![PostgreSQL](https://img.shields.io/badge/PostgreSQL-15%2B-blue)](https://www.postgresql.org/)

> **Эталонная реализация архитектурного паттерна Safe Buffer** для стыковки внешних мобильных вебхуков (Telegram Mini App, Web-виджеты) с закрытыми корпоративными и медицинскими информационными системами (МИС) без проброса сетевых портов и с соблюдением требований 152-ФЗ.

---

## Архитектура решения

```text
[Клиентский контур]
  │
  ├── Telegram Mini App (TMA) ──┐
  │   (нативный контакт,        │
  │    initData HMAC, UUID)      │
  │                              ▼
  └── Резервный веб-виджет ──────┼──► [Шлюз Traefik v3.1]
      (SmartCaptcha, валидация)  │     (TLS 1.2+, Rate Limit: 10/min burst 30)
                                 │
                                 ▼
                     [n8n Workflow Engine]
                     (Валидация initData/капчи, проверка согласия)
                                 │
                                 ▼
                     [PostgreSQL 15 Core]
                     ├── pg_advisory_xact_lock (сериализация по ключу)
                     ├── create_booking (транзакция: users + bookings + consents)
                     └── Транзакционная очередь (FOR UPDATE SKIP LOCKED)
                                 │
        ┌────────────────────────┴────────────────────────┐
        ▼                                                 ▼
[Основной воркфлоу n8n]                         [Фоновый Outbox Cron]
   │ (мгновенная отправка)                         │ (ретраи при сбоях с backoff)
   └──────────────────────────┬───────────────────┘
                              ▼
                [Дежурный чат Telegram]
                (Обезличенная карточка: #142, филиал, окно)
                              │
                    [Принять в работу]
                              │
                              ▼
                [Атомарный UPDATE status='accepted']
                (Закрепление за админом, деактивация кнопок у коллег,
                 перенос данных в закрытую МИС через локальный VPN)
```

## Ключевые возможности

1. **Сериализация конкурентных гонок (Advisory Locks):** функция `create_booking` берет `pg_advisory_xact_lock` по 64-битному хэшу ключа идемпотентности. Параллельные запросы выстраиваются в очередь на уровне СУБД, исключая дубликаты.
2. **Жизненный цикл ключа (Client-Server Idempotency):** привязка UUID к сессии и пользователю с автоматическим распознаванием повторных запросов (`is_duplicate = true`) и мгновенным возвратом существующего ID без повторной отправки уведомлений.
3. **Изоляция статуса контакта:** строгий запрет клиентскому фронтенду передавать верифицированный статус телефона. Статус `telegram_contact` присваивается исключительно доверенным ботом на бэкенде.
4. **Транзакционная очередь (Inline Outbox):** гарантированная доставка заявок дежурным с экспоненциальным backoff и выборкой `FOR UPDATE SKIP LOCKED`.
5. **Комплаенс 152-ФЗ (Strict Minimal):** медицинский анамнез и данные о здоровье исключены из открытого буфера и собираются строго внутри клиники. Персональные данные в буфере псевдонимизированы и защищены процедурой деперсонализации.

## Стресс-тестирование (`tools/test_stress_idempotency.py`)

Скрипт проверяет систему на 4 сценария устойчивости:
* **Тест 1:** Конкурентная гонка (20 параллельных потоков с одним ключом идемпотентности) ➔ ровно 1 запись в БД, 19 распознаны как дубликаты, 0 ошибок транзакций;
* **Тест 2:** Последовательный повтор с тем же ключом ➔ корректный возврат существующей записи;
* **Тест 3:** Попытка кражи ключа другим Telegram пользователем ➔ блокировка с кодом 23505;
* **Тест 4:** Попытка кражи ключа другой веб-сессией ➔ блокировка с кодом 23505.

### Запуск тестов:

```bash
# 1. Установите зависимости
pip install psycopg2-binary

# 2. Запустите стресс-тест
python tools/test_stress_idempotency.py
```
